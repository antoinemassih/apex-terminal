# Design-System Port Handoff — apex-terminal (Rust/egui)

_Created 2026-05-29. Complements `AGENT_BRIEF.md` (general project context). This doc is
specifically about porting the **design system / theming / ui_kit look** from the React
reference mockup into this Rust app._

## The setup

There is a companion **React + Vite mockup** at
`C:\Users\USER\documents\development\ApexTerminalThemes\terminal\` that renders ONE trading
terminal under **6 design systems** (Aperture, Cadence, Alto, Mariner, Lucid, Meridien). It was
built as the **styling source of truth** for THIS Rust app — the 6 theme palettes and each
theme's spacing/elevation/accent personality were tuned there to ~90% source fidelity (faster
to iterate in CSS than in egui), then are meant to be ported back here.

**Read these on the React side before porting (in order):**
1. `ApexTerminalThemes/terminal/HANDOFF.md` — full React state + a React→Rust mapping section.
2. `ApexTerminalThemes/terminal/PRIMITIVE-PARITY.md` — **the bridge doc.** It was generated by
   reading THIS repo's `src-tauri/src/ui_kit/widgets/` and mapping each Rust widget to its React
   counterpart, flagging which variants/states differ. Use it as the authoritative to-port list.
3. `ApexTerminalThemes/terminal/FIDELITY-AUDIT.md` — per-theme fidelity scorecard.

The React token values live in `ApexTerminalThemes/terminal/src/global.css` in
`[data-ds="<theme>"]` blocks (one per theme) — these `--ds-*` custom properties are the canonical
tuned numbers (gap/font/radius/stroke/alpha/heights/tracking + colors bg/fg/accent/bull/bear/border).
Each React primitive file has a header comment `// mirror of Rust ui_kit/widgets/<x>`.

## Suggested port order (propose a plan before editing)

1. **Audit the current Rust theme/token system** — read `style.rs`, `tokens.rs`,
   `widgets/theme.rs` to learn how themes are defined/switched today and which tokens already exist.
   Don't assume; the React side is the *target*, not necessarily the current Rust shape.
2. **Tokens first** — get the 6 theme palettes' token values (from React `global.css`
   `[data-ds=...]`) represented in the Rust token/theme structs, with a theme switch analogous to
   the web `data-ds` attribute. Tokens unblock everything else.
3. **Per-widget variant parity** — walk `PRIMITIVE-PARITY.md`'s PARTIAL/MISSING rows and bring the
   Rust widgets up to the variants/states the React side now supports (e.g. Tabs treatments,
   Button tones, Checkbox tri-state, Tag/CountChip tones). React-only items (AppShell, the SVG
   charts, OrderBook/LadderRow) are web stand-ins — the Rust app has its own chart/layout engine,
   so DON'T port those as primitives.
4. **Per-theme personality** — translate the per-theme spacing/elevation/accent overrides (the
   hardest-won part) into the Rust render code so each theme looks distinct, not just recolored.
