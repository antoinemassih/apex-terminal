## 1. VERIFIED P0 — order-path holes (fix before anything else)

### P0-1. Raw market orders bypass OrderManager entirely
`ui/panels/orders_panel.rs:170-200` — the positions panel's **"Close position"**
and **"½" (half-size)** buttons spawn `reqwest::blocking::Client::new().post({APEXIB_URL}/orders,
{"orderType":"market"})` directly. This bypasses: kill-switch, halt, daily-loss cap,
buying-power, fat-finger, max-qty, **paper_mode guard**, dedup, WAL journal, and
order state tracking. If ApexIB is pointed at live TWS, these are unguarded live
market orders. Same raw-HTTP family: `orders_panel.rs:249` + `top_nav.rs:1325,1334`
+ `command_palette/execute.rs:187-214` + `keyboard_shortcuts.rs:409` (flatten /
cancel-all / reverse / halfsize). Flatten & cancel-all are risk-*reducing* (and
arguably should work even when kill is engaged — kill's own flatten uses the same
endpoint), but they still skip journal/audit/state; close-position and halfsize
create NEW market orders and are the real hole.
**Fix:** route close/half through `OrderManager::submit()` (market intent,
`OrderSource::PositionsPanel`); give flatten/cancel-all first-class OrderManager
methods (kill-path-adjacent, journaled, allowed-under-kill). Then add a CI ratchet:
zero `reqwest` in `ui/` (the E7 lint, pulled forward for the order endpoints).

### P0-2. Bracket/OCO: Working-before-Ack + NO rollback on submit failure
`order_manager.rs:1567-1587` (bracket), ~1700 (OCO): all legs `transition(...,
Working)` synchronously right after spawning the HTTP call — before broker Ack,
before backend IDs are wired. Worse: the spawned thread's `Err` branch only
`report()`s — **a failed bracket submit leaves 3 phantom Working orders with
`backend_order_id=None`, forever**. The A2 fix (PendingSubmit-until-Ack) was
applied to plain `submit()` but never to bracket/OCO/conditional/trigger/combo.
**Fix:** parity with A2 — stay `PendingSubmit`, transition to Working inside the
spawned Ok-branch (with backend IDs), transition to Rejected in the Err branch.
Also reconcile per-leg partial acceptance (broker accepted entry+TP, rejected SL
→ cancel accepted legs or alert loudly: unhedged).

### P0-3. Market-order buying-power check is dimensionally wrong
`order_manager.rs:910-916`: for market orders it compares `qty >= 0.95 * bp` —
**share count vs dollars**. A 1,000-share market order on a $500k-notional stock
passes on a $100k account; a legitimate 480-share order on a $500 account is
spuriously rejected. Market orders also skip the fat-finger check entirely
(:869-881), so a huge market order gets no deviation warning either.
**Fix:** estimate notional from last trade/mid (`intent.last_price` or snapshot)
and run the same `notional + inflight > bp` check as limit orders; apply
fat-finger to the implied execution price.

## 3. SOLIDIFY — the money-path test gap (highest-value tests to add)

The corpus (1,067 scenarios) guards *UI behavior*; the order lifecycle's hardest
paths have thin unit coverage. Ranked:

1. **State-transition matrix test** — `transition()` (order_manager.rs:2462) allows any→any; assert Filled/Cancelled/Rejected are terminal, PendingSubmit's 3 legal exits, etc. (S)
2. **WAL rotation & crash-replay** — journal/wal.rs:76-143 has ZERO tests (10MB rotation, merged read order, duplicate-free replay). (M)
3. **Risk-boundary tests** — daily-loss at exactly the cap; BP with inflight stacking; the P0-3 fix regression test. (S, alongside P0-3)
4. **Bracket/OCO fill-linking** — entry fills → sibling PendingCancel→Cancelled; race: sibling already filled → no double-cancel; the P0-2 Err-branch rollback. (M)
5. **Conditional trigger eval** — `≥/≤` boundary at exact equality; already-past-trigger backfill. (S)
6. **Serde round-trip for every persisted struct** — ManagedOrder full-field round-trip; old-version JSON loads with defaults (schema-migration test on the persistence envelope). (S)
7. **Test-infra unlock:** `APEX_ORDERS_STATE_PATH` env override (mirroring `APEX_WAL_PATH`) so order persistence is disk-testable; Watchlist::new() loader injectable. (S — unlocks most of the above)
8. **<500-prefix scenario hermeticity** — ~420 scenarios unguarded because the app runs on real user state. A `/reset-state` dev_inspector command + pre-scenario reset would bring layout/persist scenarios into the gate. (M)
