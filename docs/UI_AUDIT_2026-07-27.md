# Apex Terminal — UI / Design Audit
**2026-07-27 · 11 dimensions · 11 parallel digger agents · every claim file:line-cited**

Purpose: map every corner of the UI to plan a **big UI polish + design tune-up**, not to fix functional bugs (though a few real ones surfaced and are flagged P0). Companion to `WORLD_CLASS_AUDIT_2026-07-18.md`; same actionable shape.

## Method
Eleven Sonnet agents, one per UI dimension, each read-only with hard evidence discipline (`file:line` for every claim) and a polish/design lens (visual consistency, design-system adherence, identity). Dimensions: design tokens & `sx`; typography & text rendering; color/theming/contrast; core widgets; panels & chrome; toolbar/top-nav; interaction & motion; iconography; layout/spacing/density; feedback/status + chart chrome; holistic IA / world-class lens. Full per-agent transcripts in the session task dir.

## 1. Executive read

Apex Terminal has an **unusually complete, well-engineered design system that production largely bypasses.** The bones are ahead of the skin: a real two-axis theme system (21 `ColorScheme`s × 9 `StyleSystem`s), token scales for spacing/radius/type/motion, a GPU subpixel-AA text pipeline, a WCAG validator, a rail registry + shared side-panel shell, and ~99 kit widgets with a consistent builder API. Spacing/font/radius token adoption is genuinely high (~90–95%).

But **the single dominant finding, repeated independently by all 11 agents, is an ADOPTION GAP**: a dozen polished, well-documented components sit at ~0% production use, each next to a hand-rolled reimplementation of itself. This is the same defect class the code audit hit six times — complete, tested logic with zero callers — now pervasive in the UI layer. It means most "polish" is not *design new things*; it's **adopt and unify what already exists**, which is far higher-leverage and lower-risk.

Two other themes stack on top: (a) **theme-bypassing hardcoded values** — a parallel color palette, ~428 raw `Color32` literals, ~153 raw glyph/emoji usages competing with the Phosphor set, off-scale font sizes; and (b) **a borrowed visual identity** — themes literally named Nord/Dracula/Monokai/Gruvbox; the product "wears the visual identity of a code editor" rather than having its own gravity (Bloomberg amber, TradingView blue, Bookmap heat).

There is also an authoritative external target already in the repo: `DESIGN_PORT_HANDOFF.md` → the `ApexTerminalThemes` React reference with `FIDELITY-AUDIT.md` / `PRIMITIVE-PARITY.md`. The polish work has a source of truth to converge on.

## 2. Already world-class — protect these
- **Two-axis theme architecture** (`design_system/color_scheme.rs`, `style_system.rs`): 21 schemes × 9 styles, cleanly separated, all structurally consistent.
- **A correct WCAG validator already exists** (`design_system/theme_pack/validate.rs:391-467`) — it's simply never run against shipped themes.
- **Token/override-multiplier system** (`ui_kit/style.rs`): one atomic flip re-scales spacing/radius/stroke/motion app-wide.
- **Motion system** (`ui_kit/widgets/motion.rs`): shared curves, damped spring, drag-gated repaint, `MotionSpeed::Off` kill switch. Tab bar already animates.
- **Order-line lifecycle chrome** (`render/pane/core.rs:12699-12743`): 7 states → distinct pulse/dash/alpha, documented. Best chart chrome in the app.
- **Rail registry + `SidePanelShell`** (`ui/panels/right_rail.rs`, `side_panel_shell.rs`): one-line dockable panels; unified header/close/tabs across 27 panels.
- **GPU subpixel-AA text pipeline**, real placement/auto-flip overlay engine, colorblind-safe redundant encoding in `regime_tape.rs`, kit theme contract with first-class hover/active/disabled colors. Real font-level monospace-for-digits policy.

## 4. P0 — real correctness bugs (not just polish)

These are genuine defects, several theme- or accessibility-breaking:
1. **9/21 themes + both hand-written defaults fail WCAG AA (4.5:1) on `dim`/`bg` text** — Kanagawa 2.55:1, Midnight 3.45, Rosé Pine 3.42, Lucid 3.13, plus Bauhaus/Peach/Ivory/Newsprint; `default_dark` 4.24, `builtin_light` 3.62. `dim` is ~118 sites. The validator to catch this exists but is never run against shipped themes. (`design_system/builtin.rs`, `theme_pack/validate.rs`)
2. **Parallel hardcoded palette breaks P&L color under non-default themes** — `chart/renderer/ui/style.rs:764-810` (`COLOR_PROFIT_GREEN`/`COLOR_LOSS_RED`/`TEXT_PRIMARY`…) consumed in `render/pane/core.rs:35,10770,10782` — profit/loss labels stay generic red/green under Monokai/etc. instead of the theme's bull/bear.
3. **Crosshair / time-axis text hardcoded `Color32::WHITE`** on a theme-variable fill (`core.rs:6991-7039`) → contrast failure under the real light theme. The one true rendering-correctness bug in chart chrome.
4. **Tab close-X only works on the active tab** — `chart.tab_hovered` is never set, so inactive tabs can't be closed without activating first (`painter_pane.rs:791-792`, `gpu.rs:2565`). Plus **no tab-overflow strategy** — many tabs silently overlap the action cluster.
5. **Option badge painted across unrelated stock tabs** sharing a pane (`core.rs:536-538` / `painter_pane.rs:772-778`).
6. **Toast pin icon bug** — both branches identical: `if is_pinned { PUSH_PIN } else { PUSH_PIN }` (`top_nav.rs:1777`).
7. **"Suites" submenu ships permanently-disabled placeholder rows** ("Triangulator", "Auto Target") with no tooltip — the lying-button pattern the P0 Trust sweep explicitly fixed elsewhere (`chart_controls.rs:738-739`).
8. **`Label::truncate(true)` silently wraps instead of eliding** (`label.rs:116-124`) — misleading API; will break row layouts when adopted.
9. **3 toolbar icon collisions** — `BROWSERS`, `MAGNIFYING_GLASS`, `CHART_LINE` each reused for two unrelated actions (`top_nav.rs:713/1135, 1103/1228, 1267/1268`).

## 5. Findings by dimension (condensed — full evidence in transcripts)

**Design tokens / sx.** Color has two live tint systems ~50/50 (`color_alpha` 524 sites vs `palette_ct`/`shade` 474); pick one canonical. Per-preset `StyleSettings` dims (row/button/tab heights, card padding) restate raw px instead of deriving from the global tier via a multiplier. Two "recipe" systems (unused compile-time `Recipe` vs live `RecipeSpec`) — disambiguate. Declared-canonical tiers (`card_padding_*`, `divider_inset_*`) have 3–4 callers — wire or delete.

**Typography.** Line-height computed for all 14 `TextStyle` variants but `as_rich()` never reads it. `TextStyle` ~7% adopted (406 raw `RichText`). Dead tiers (`Display`, `HeadingLg`, `NumericHero`); `font_2xl()==font_lg()` alias collision. Off-scale sizes (18/24/34/36) in real panels. Hero numeric readout switches to proportional serif under Meridien → digits jiggle. ~19 distinct sizes in use.

**Color / theming.** See P0s. Also: 3 parallel default-palette sources to reconcile (`ColorScheme::default_dark`, legacy `gpu::THEMES`, `PortableTheme`); extended semantic axis (`success/danger/warning/info`) 0/21 used; 5 themes have bull/bear luminance gap <0.05 (hue-only, colorblind-unsafe); ~428 raw `Color32` literals (>100 in production paths, worst `core.rs` 32).

**Core widgets.** Focus ring on <half of keyboard widgets; disabled-border missing on Input/TextArea/Select; `Size::Md` renders two different point sizes; loading state on Button only. `Variant` grown to 14 (Chrome escape-hatch still 23 sites); button.rs has 17 constructors + 5 show-paths. Six color-role enums resolve to ~5 colors. Overlay corner-radius has 4 undocumented tiers; Modal has no Escape-to-close. **12 duplicate clusters** (chip/pill/tag; card/panel; tone enums; Popover/ToolPopover; Tooltip/HoverCard; numeric-widget size scales; …). SegmentedControl connected/separated radius branches byte-identical.

**Panels.** `SidePanelShell` 27/60, `PanelSection` well-adopted; `PanelError` 0 adopters; dead `kit.rs` `PanelSection`/`PanelEmpty` shadows; `scanner_panel` double-title bug + skips `PanelSection`; `order_ledger_panel`/`script_panel` hand-roll empty/card; RRG/msg-* panels show demo data with no live/demo badge; `dom_panel` fully bespoke chrome (intentional but drifting).

**Toolbar.** Two mega-clusters (10-button panel toggles; 6-feature `tools_box`) with no sub-grouping; icon collisions; IBKR button hand-builds glyph; window controls have zero tooltips; tab bar overflow/close bugs; `alert_feed`/`window_controls` bypass the kit; connection state coded 2 different ways (glyph vs hue-only). **Biggest single lever: retire hand-rolled `painter_pane.rs` header onto the dormant `chrome/pane.rs`.**

**Interaction / motion.** Inspect-mode cursor gate honored by ~15 of 70+ call sites → the design inspector fights the live cursor (blocks reliable use of the tool for the whole polish pass). Toast has no exit fade (Modal has the pattern). `selectable_row` hover snaps vs eased elsewhere. MenuItem no focus ring. `price_flash_tint` exists but not applied to order/alert rows. Micro-interaction wishlist: fill-confirmation flash, toast exit, toggle overshoot, divider hover accent.

**Iconography.** ~153 raw glyph/emoji usages across 45 files competing with the Phosphor set; 7 concepts with 2+ competing icons (close, warning, check, search, caret, up/down, status dot); full-color emoji (🔍📋📎✦👁📖) in a monochrome instrument UI; honest coverage gaps (`// no Phosphor equiv` for droplet/briefcase) — extend the `Icon` catalog. Kill raw `✕` via `Button::close()` (correct widget already exists, 100+ callers).

**Layout / spacing.** Spacing scale honored (712 vs 48 raw, 30 of 48 in one demo). Pane header heights (28/24/22/18) have no single token; near-token literals hand-typed (`8.0` where `gap_sm()==8.0`); divider insets differ 3px/4px across 3 helpers; close hit-targets 14 vs 18; no responsive/overflow for narrow panes; two dead pane-chrome systems.

**Feedback / chart chrome.** 4 status vocabularies + 3 toast systems (see adoption table); `PanelError`/`ConfirmDialog` unused; hardcoded white axis text (P0-3); fake-bold 0.5px double-draw; 4 corner-radius conventions on-canvas. Order-line chrome is the strength to extend.

**Identity / IA.** No signature palette (editor-named themes); 135 theme×style combos in one settings tab with no curated default; 3 unaudited style systems (Octave/Relay/Glass) beyond the React reference's 6; redundant Scanner (2 homes); "junk drawer" Analysis panel; plain-text context menus. **Top lever: ship ONE signature Apex palette as the flagship default, demote editor reskins to a "classic" tier.**

## 6. Staged polish execution plan

Ordered for leverage and trust: clean/wire first (removes landmines, makes everything else land on real surfaces), then correctness, then the visible identity win, then consolidation, then chrome/motion refinement. Every code-touching item gets the corpus gate (`python dev/run_corpus.py`, 1067/1067) since these touch render paths.

### Wave U0 — Foundation: delete dead duplicates + wire the orphaned components  [highest leverage, lowest risk]
- Delete dead: `kit.rs:584-767` shadow widgets; `shell_variants` zero-caller enums; `ContextMenu` (507 LOC); `PaneGrid` render half; `Tree`; zero-caller `button.rs` constructors; button_style dead impls. `log()` what's removed.
- Wire orphans into production: `StatusPill` (→ dom/bottom_dock/portfolio status), `PanelError` (→ scanner/screener/connection fetch failures), `PanelLoading` (→ the ~17 ad-hoc loaders), `ConfirmDialog` (→ destructive actions), unify the 3 toast systems onto `ui_kit::Toast`.
- Fix the scanner double-title + stale `SplitSectionPanel` doc comments.

### Wave U1 — Correctness & accessibility  [fast, high-trust]
- Run `theme_pack::validate::check_accessibility` as a `#[test]` over all built-in schemes + defaults; fix the 9 failing `dim` values to ≥4.5:1.
- Kill the parallel hardcoded palette (`ui/style.rs:764-810`); route P&L color through `t.bull()/t.bear()`.
- Fix crosshair/axis hardcoded white → `contrast_fg(t.toolbar_bg)`.
- Close the focus-ring gap (~11 widgets) + disabled-border gap (Input/TextArea/Select) via the existing helpers.
- Fix the functional bugs: tab close-on-inactive + tab overflow, option-badge-across-tabs, toast pin icon, Suites lying-buttons, `Label::truncate` ellipsis, 3 icon collisions.

### Wave U2 — Signature identity  [the visible "wow"]
- Design + ship ONE bespoke Apex palette as the flagship default; demote editor themes to a "Classic/Developer" tier. Converge on the `ApexTerminalThemes` React reference (`FIDELITY-AUDIT.md`).
- Collapse the Theme×Style settings into curated "Looks" (pre-paired combos + recommended badge; "mix your own" behind Advanced). Cut or finish the 3 unaudited style systems.
- Typography adoption sweep: wire line-height into `TextStyle::as_rich()`; migrate the worst off-scale sizes; prune dead tiers + fix the `font_2xl` alias; decide hero-number font (keep tabular mono).
- Iconography unification: replace raw `✕/⚠/✓/▲▼/🔍/…` with `Icon::*`/`Button::close()`; extend the catalog for the admitted gaps; kill emoji in chrome.

### Wave U3 — Component consolidation
- Merge the chip/pill/tag family → one `Chip` + one tone enum (`sx::Tone`); merge the card/panel-container family; merge overlay pairs (Popover/ToolPopover, Tooltip/HoverCard); collapse the 6 color-role enums; unify the 4 numeric-widget size tables onto `tokens::Size`; prune `button.rs` API to Variant+Size and finish the `Variant::Chrome` cleanup (23 sites).
- Fold per-preset `StyleSettings` dims onto the global tier via multipliers; pick one canonical color tint system and finish/freeze the other.

### Wave U4 — Chrome & motion refinement
- Retire hand-rolled `painter_pane.rs` header onto `chrome/pane.rs` (fixes tab bugs, missing tooltips, faux-bold in one coordinated pass); add tab overflow.
- Toolbar hierarchy pass: group primary/secondary/chrome with real dividers; give panel-toggle nav items icons.
- Chart chrome refinement: axis type scale, gridline weight/color, a distinctive candle/wick treatment (on-screen 100% of the time), one radius convention.
- Motion language: extend the rail's easing to panel open/close, tab switches, modal entry; add toast exit fade; micro-interactions (fill/alert flash via existing `price_flash_tint`, toggle overshoot, divider hover accent). Route all pane cursors through `ui_kit::cursor` so the inspector works.
