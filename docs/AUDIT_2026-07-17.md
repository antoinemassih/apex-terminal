# Apex Terminal — End-to-End Doc/Code Audit, 2026-07-17

**Method.** Five parallel auditors, one per doc cluster (trading/DOM, audit-claim
verification, state/storage, design-system/UI, data/GPU/backtest specs). Every
auditor was briefed to **distrust the docs and prove each claim against code with
file:line evidence**, to say UNSURE rather than guess, and to flag live-money
issues as P0. Findings below were spot-verified by hand where they were most
consequential.

**Headline.** The dominant defect class in this codebase is **parallel or partial
implementations that read as complete**, and documentation that is unreliable in
*both* directions:

- Docs that **overstate**: the WS-H remediation fixes landed on the sites named in
  each shortlist and stopped there, while commit titles and doc status read as
  closed. Three live-money residuals below are recorded as fixed and are not.
- Docs that **understate**: the state layer and design system have quietly
  *overtaken* their roadmaps, so those docs describe work already shipped and
  send readers to re-plan finished work.

Treat the audit docs as a reliable map of **where** the bugs are and an unreliable
record of **whether** they are closed.

## P0 — live money / data integrity

### 1. Plays bypass OrderManager and collide with real order IDs
`plays_panel.rs` `convert_play_to_orders` invents its own ids
(`chart.orders.iter().map(|o| o.id).max().unwrap_or(0) + 1`) and pushes
`OrderLevel`s straight into `chart.orders` — **zero `order_manager` references in
the function**. OrderManager independently allocates from `next_id: u64` starting
at **1** (`order_manager.rs:744, 1230`), surfaced as `id: self.id as u32` (`:413`).
`orders_view` merges **by id** (`trading/mod.rs:83`).

The DOM ladder renders `Draft` *and* `Placed` as working chips
(`dom_panel.rs:567`). Consequences:

- A play-derived phantom appears on the live ladder as a working order.
- Dragging one with no matching manager id → `modify_price` returns `false`
  **silently** → "the drag doesn't take" (user-reported, 2026-07-17).
- Dragging one whose invented id **collides** with a real order → the modify is
  applied to the **real broker order**.

`DOM_TRADER_DESIGN.md`'s invariant ("nothing here bypasses OrderManager") is
false. Other direct writers of the parallel store: `gpu.rs:1817/1820/1859/1862`,
`commands.rs:1024`.

**Fix direction:** give play-derived levels a disjoint id namespace (or route them
through OrderManager as Drafts). Until then the ladder is not trustworthy for
play-derived orders.

### 2. Working-before-Ack fixed for only 3 of 6 submit paths
`AUDIT_2026-07-10` P0-2 scoped the fix to "bracket/OCO/**conditional/trigger/
combo**". Commit `40c0bff9` did bracket + OCO. Still synchronous `Working` before
broker Ack on the **live** path, with `Err` branches that only `report()`:
`order_manager.rs:2033` (conditional), `:2144` (options-trigger), `:2267` (combo).
Correct pattern for contrast: `:1706-1742` (bracket), `:1879-1919` (OCO).

**Impact:** a failed submit leaves a permanent phantom `Working` order with
`backend_order_id=None` — uncancelable. **Docs record this as closed.**

### 3. Kill/halt re-check exists in exactly 1 of 7 spawned threads
Only `submit()` re-checks (`order_manager.rs:1344`). `confirm()` (`:1513`),
bracket (`:1686`), OCO (`:1867`), conditional (`:2020`), options-trigger
(`:2130`), combo (`:2254`) go straight to `broker.submit*`. P1-2's fix text said
"each spawned thread"; commit `78f9ecf9` did one.

**Impact:** orders queued before Ctrl+Shift+K still reach the broker via 6 of 7
paths. **Docs record this as closed.**

### 4. No market-data staleness gate on the order path (#48, still open)
Submit gates are kill-switch / halted / rate-limit / qty / max-open / oversell
only (`order_manager.rs:1147-1221`). `halted` is auto-set solely by *broker*
contact age (`:3952-3966`), never market-data age. The buying-power/notional
pre-check consumes an apex_data snapshot with **no age check** (`:965-979`).
`live_state.rs:35` stores `(Snapshot, Instant)` but `get_snapshot` (`:444`)
**discards the Instant**; eviction is watch-set membership, never age
(`:203-207`); poll errors are swallowed (`:187-198`).

**Impact:** a dead poller serves the last-good price indefinitely as current, and
risk checks size against it. The correct pattern already exists in this repo —
the DOM's 2s freshness gate (`core.rs:1456-1457`, `dom_panel.rs:662`) and
LIVE/SIMULATED badge — it was simply never applied to the order path.

### 5. Backtest button fabricates unlabeled performance statistics
`script_panel.rs:183` calls `mock_backtest()` (`:64-114`) — a seed=42 LCG that
**ignores the script source entirely** — then renders Total P&L, Win Rate, Profit
Factor, Max Drawdown and **Sharpe Ratio** (`:186-191`, `:314-317`) with **no
mock/simulated marker in the UI**. "Run" emits fake "Bars processed / Signals
generated" (`:175-176`). Only disclosure is a source comment (`:4`).

**Impact:** invented risk statistics presented as real in a real-money app. This
is the same class as the gamma-synth issue, which *was* badged (F3). Either badge
it SIMULATED or remove the panel until an engine exists (see #10).

### 6. drawing_db silently discards user drawings on exit
Retry exists (`drawing_db.rs:28` `SAVE_MAX_ATTEMPTS=3`, backoff `:61-75`), but on
exhaustion the drawing is parked in an in-memory `VecDeque` capped at 64
(`:53-87`) that is **never drained or re-persisted** — process exit drops it.
`save()` (`:142`) is fire-and-forget with no ack, so the UI shows the drawing as
saved. Postgres is the canonical drawing store (`workspace_persist.rs:104-107`
deliberately omits drawings from workspace JSON *because* they live in PG), so a
dropped save is **unrecoverable user data loss**.

### 7. No snapshot-superset test exists
The state roadmap's Phase 0/3 exit criterion — a `#[test]` per aggregate
asserting the persisted snapshot is a superset of the live struct — was never
built (grep `superset|parity|snapshot_completeness` → only an unrelated
`design_system/snapshot.rs:35`). The one guard designated to catch silent field
loss does not exist, while the dual-write it was meant to protect is still live
(see P1).

## P1

- **Market orders still skip fat-finger entirely** — `order_manager.rs:914` guards
  `order_type != Market`. The BP notional half of P0-3 *was* fixed (`:952-1005`);
  the fat-finger half was not. The `None`-price branch (`:989-996`) fail-opens the
  BP check by design.
- **`control_flags` fail-closed covers parse errors only** — `order_manager.rs:60-64`
  fail-closes on serde error, but the outer `if let Ok(bytes) = fs::read` (`:46`)
  swallows **all IO errors** (permission denied, locked, disk) identically to
  file-missing → `kill_engaged` stays `false`.
- **Dual-write still live; Phase 3 unstarted** — `gpu.rs:5855-5857` states outright
  that "the legacy fields remain the read source of truth". 266 UI mutations write
  flat fields directly; the flat↔store bridge fires only at save/load
  (`push_all_stores` `:6609-6614`).
- **OCO/bracket risk validated per-leg, not aggregate** — `order_manager.rs:1776-1781`
  loops `validate_risk` per leg; two $30k legs pass a $50k cap. (Correctly listed
  open in the existing docs.)
- **`design-system-check.yml` is permanently RED and therefore dead signal** —
  runs on every push/PR with no `continue-on-error`; exits 1 with **454 "new"
  violations** because all 4 paths in `scripts/.design-system-baseline.txt` no
  longer exist on disk, so `comm -23` marks every real violation as new. Secondary
  bug: `ALLOWED_PATHS` matches by filename, so `*style.rs` also excludes
  `ui_kit/style.rs`.
- **`str_keyed_cache!` bounding is at call sites, not in the macro** — all 8 caches
  are bounded (`fetch.rs`, `STR_CACHE_CAP=256`) so the leak is closed, but the
  macro (`:185-196`) still emits an unbounded `HashMap`: a 9th cache is unbounded
  by default. Per-cache `inflight` HashSets remain unbounded.
- **`drain_all` has zero callers** — shutdown integrity landed as marker-only
  (`write_shutdown_marker` verified at `gpu.rs:7914`, reached from both
  `CloseRequested` and `Destroyed`).
- **`bar_cache` forming-bar fix missed 3 sites** — `foundation/types/mod.rs:132,143,164`
  (the audit named `:132` by line). Likely a dead path (`get_bars` has no live
  callers) — **UNSURE on reachability** — but the claim is false as written.
- **Daily-loss boundary is a fixed +2h UTC offset, not ET** — `order_manager.rs:3624-3627`
  (`SESSION_ROLL_SHIFT_MS`) → 17:00 EST but **18:00 during EDT**. The safety
  property (no reset mid-overnight-session) holds year-round; the commit title
  (`bf04a9a4`, "17:00 ET") overstates it.
- **`dev_inspector` hardening landed 3 of 5** — CORS, body cap, `safe_rel` verified;
  **no auth of any kind** on `127.0.0.1:7892` (`server.rs:82`), no env opt-in gate
  (`#[cfg(debug_assertions)]` only), order-effecting AppCommands not refused.
- **Phase 2 (input layer) has zero code** — `fn process_pane_input` exists nowhere;
  `core.rs` still has 14 `key_pressed` reads gated by hand via
  `pane_idx == *active_pane`.
- **12 production user-data writes bypass `atomic_write`** — `playbook_store.rs:61,219`,
  `screenshot_panel.rs:62,76`, `screener_panel.rs:166`, `spreadsheet_pane.rs:309`,
  `theme_studio.rs:733`, `pack_registry.rs:361`, `perf_log.rs:92-96`,
  `chart/state/file_io.rs:30`. **The money path is clean** — order WAL and
  control_flags do use `atomic_write` (`order_manager.rs:2615, 3125`).

1. **P0 #1** (plays/OrderManager id collision) — a phantom UI control wired to a
   real broker order.

   red gate teaches everyone to ignore CI.

   every doc-derived plan unsound.
